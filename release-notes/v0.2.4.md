# v0.2.4

## New

* **Page menu: adjustable page size and margins.** A new "Page" toolbar\
  menu lets you choose a page size (A4/Letter/Legal) and set the top,\
  bottom, left, and right margins, plus toggle the page-boundary guides\
  on or off — applies across the whole app, the same way font choice\
  already does. *(PDF export's physical paper size is still fixed to\
  A4 for now — see knowBugs.md.)*
* **Paged preview now actually has pages.** Switching the export\
  window to "Paged" mode previously just drew cosmetic dashed lines\
  over one long continuous block. It now really splits the document\
  into separate page-sized boxes, matching your chosen page size and\
  margins, without re-rendering anything — content moves to the next\
  page if it doesn't fit rather than having a line drawn through it.
* **Fully customizable PDF header/footer.** A "Headers & Footers"\
  section in the Page menu lets you set independent left/center/right\
  text in both the header and the footer — empty by default, with\
  `{title}`, `{page}`, and `{pages}` tokens usable anywhere once you add\
  your own text (e.g. "Page {page} of {pages}", or your name/subject as\
  plain text in another zone). A "blank header on first page" toggle and\
  a "first page is a title page" toggle (which also blanks the footer\
  there and starts page numbering at 1 on the page after it) make title\
  pages straightforward. A "Header & footer" checkbox in the export\
  window turns the whole thing off for a given export when exact,\
  unmodified margins matter more. Margins are now always exactly what\
  you set, in every case — header/footer content is drawn directly onto\
  the finished PDF rather than requested from the PDF engine's own, more\
  limited built-in mechanism, which couldn't do any of the above and\
  also quietly reserved extra space around itself beyond the margin\
  actually requested.
* **Footnotes.** Standard academic markdown syntax — `text[^1]` for a\
  reference, `[^1]: note text` for its definition — rendered as a small\
  superscript number with the raw syntax visible only while you're\
  editing it. Numbers renumber automatically as footnotes are added,\
  removed, or reordered. Click a reference to jump to its definition (and\
  a back-arrow to jump back), or just hover one for a quick preview\
  without leaving your place. A new toolbar button inserts a footnote at\
  the cursor and drops you into the new definition, ready to type.
* **Toolbar visual refresh.** Icon buttons across the toolbar, File\
  menu, activity bar, and sidebar use a thinner icon stroke and only\
  show their background on hover, instead of always looking like a\
  pressed chip. Still iterating on this before v1.0.
* **Undo/Redo moved into the window frame**, next to the logo,\
  instead of taking up their own toolbar section.
* **Spellcheck right-click menu.** Right-clicking a misspelled (red-underlined)\
  word now offers suggested corrections and an "Add to Dictionary" option, so\
  words like "Saguinus" or "KaTeX" stop being flagged.
* **Spellcheck language picker.** A new multi-select in Preferences lets you\
  enable additional spellcheck languages beyond English; the selection\
  persists across restarts.
* **Auto-capitalization.** The first letter typed into a new paragraph is\
  capitalized automatically.
* **Math active-state cue.** Inline math and math blocks now get a visible\
  outline while the cursor is inside them, so it's clear they're being\
  edited.
* **Heading alignment.** Headings can be aligned left/center/right from the\
  toolbar; the choice is saved in the markdown (as a trailing HTML comment)\
  and survives reload.
* **Table of contents.** A live "Outline" sidebar panel lists every heading\
  in the document and jumps to it on click; a TOC block can also be\
  inserted directly into the document, with floating Refresh/Delete\
  controls since it doesn't auto-update on its own.
* **Folder explorer.** Replaces the FILES sidebar panel entirely. Open a\
  folder from the activity bar and browse it as an expandable file tree;\
  once a folder is open, relative image/link paths in the document resolve\
  against it instead of requiring a full absolute path.
* **Paste and drag-and-drop images.** Copying or dragging a real image file\
  links to it in place at its existing path; copying raw clipboard image\
  data (e.g. a screenshot) writes it to a new file under an `assets/`\
  folder next to the document.
* **Draggable, viewport-aware link/image popups.** The floating popups for\
  editing a link or image no longer spawn off-screen for large images, and\
  can now be dragged to a different spot by clicking their background.
* **Code block syntax highlighting.** Code blocks are now colorized\
  in-place by language, applied directly to the real text (not a separate\
  overlay).
* **"Open with Saguinus."** `.md`/`.markdown` files can be opened directly\
  from the OS (right-click → Open with, or via the file association\
  registered by the installer). Opening another file while Saguinus is\
  already running adds it as a tab in the existing window instead of\
  starting a second instance.

## Fixes

* **Multi-tab autosave/dirty-tracking fix.** Autosave timing and the unsaved\
  changes (*) indicator are now tracked per open file/tab instead of\
  globally, so editing across multiple open documents no longer\
  cross-contaminates autosave timing or dirty state between tabs.
* **Pages render correctly after switching tabs.** Switching tabs loads the\
  new document via `EditorState.create`/`updateState`, which bypasses the\
  normal transaction pipeline — page-height recalculation now fires\
  explicitly on tab switch instead of only on the next real edit.
* **Images in folders with spaces now survive reload.** Image paths\
  containing a space failed CommonMark's link/image destination syntax and\
  silently reverted to literal text after switching tabs or reopening a\
  file. Such paths are now wrapped in `<...>` on save and decoded back to a\
  clean path on load.
* **`store.json` could silently lose recent files/session data.** A crash\
  mid-write could truncate the file; the very next save would then\
  overwrite it with empty defaults, permanently losing the real data.\
  Writes are now atomic (write-to-temp + rename) and serialized, and a\
  corrupt file is preserved for inspection instead of being clobbered.
* **Dragging a file onto the window could navigate the whole app away.**\
  Electron's default reaction to an unhandled file drop is to navigate the\
  renderer to that file, wiping out the app entirely. A window-level guard\
  now prevents this.
* **A failed paste/drop could permanently freeze the editor.** A blocking\
  `alert()` shown from inside a paste/drop handler could wedge the\
  window's focus and keyboard input routing even after being dismissed.\
  Errors are now reported via a non-blocking on-screen message instead.
* **Pasting a real image file unnecessarily required a folder.** Modern\
  Electron removed the `.path` property from `File` objects; pasted/dropped\
  files are now resolved via `webUtils.getPathForFile` so real files link\
  directly without needing a workspace folder or saved document.
* **Code block syntax highlighting did nothing.** The Shiki plugin was\
  built but never registered with the editor, so it silently had no\
  effect; it's now wired in, and rewritten to highlight the real text\
  directly instead of an unstyled overlay copy.
* **PDF export ignored the chosen font/size.** Font settings are applied\
  via attributes on `<html>`; the export copied the matching CSS rules but\
  never the attribute values, so nothing matched and it always fell back\
  to the default font/size.
* **PDF export's filename and embedded title were disconnected from\
  reality.** The save dialog always suggested `"document.pdf"` regardless\
  of the open document, and the PDF's embedded title was set from the\
  in-app document name before the save dialog even ran, so it never\
  reflected whatever name was actually chosen. Both now derive from the\
  real filename.
* **Pasting multi-line text into a code block mangled it.** Paste was\
  always run through the Markdown parser, which collapsed every line\
  break into a space and could split an indented line off into its own\
  separate code block. Pasting while the cursor is inside a code block\
  now inserts the text exactly as copied.
* **Converting a selection to a code block dropped all its line breaks.**\
  Fixed a missing argument that caused line breaks within the selection\
  to be silently skipped instead of carried over.
* **The code block language picker only appeared after editing, not on\
  click.** It now appears as soon as the cursor enters the block.
* **Code blocks defaulted to "bash" highlighting even when nothing was\
  set.** New code blocks (and ones with no recognized language) now\
  default to plain text instead of being colorized as if they were bash.
* **PDF export lost code block syntax highlighting colors**, reverting\
  to a plain light box — left over from before real syntax highlighting\
  existed. Code blocks now keep their dark, colorized appearance in\
  exported PDFs.
* **Pasting a code block copied from an AI chat app (ChatGPT, Claude.ai,\
  etc.) landed as plain text, not a code block.** Paste now checks the\
  clipboard's rich HTML for `<pre><code>` structure even when plain text\
  is also present, and rebuilds it as a real, syntax-highlighted code\
  block (detecting the language where available) instead of flattening\
  it into a paragraph.
* **Changing a code block's language from the dropdown never actually\
  saved.** It updated the live syntax highlighting only; the saved\
  file's fence line was written from an attribute that didn't exist on\
  this app's code block at all, so the language was silently dropped\
  on every save. Language changes now persist correctly.
* **Undo/redo did nothing.** The history plugin was loaded but had no\
  button or keyboard shortcut wired to it. Added Undo/Redo toolbar\
  buttons and the standard Ctrl+Z / Ctrl+Y (Ctrl+Shift+Z) shortcuts.
* **Switching tabs wiped undo/redo history.** Every tab switch rebuilt\
  the editor from scratch, discarding history even though the document\
  itself was preserved. Each open tab now keeps its own undo/redo\
  history for the life of the app session; only actually closing a tab\
  clears it.
* **Critical: reopening the active tab could silently roll back and\
  then permanently overwrite a file with stale content.** A side\
  effect of the undo/redo-history fix above — clicking a tab that was\
  already open and active (or reopening the same file from Recent\
  Files) could restore an old in-memory snapshot of it, instantly\
  undoing everything typed since, and autosave would then save that\
  rollback to disk a few seconds later. Reopening the already-active\
  tab is now a strict no-op.
* **Critical: the last tab restored from a previous session could be\
  silently blanked and saved over, even without ever clicking it as\
  "active."** A second, distinct cause of the same class of bug —\
  session restore left some internal bookkeeping pointing at the\
  wrong tab, which could make the very last tab a session restored\
  look blank the first time you opened it, with autosave then writing\
  that blank content over your real file. Fixed at the source.
* **Added file backups, so this class of bug can't destroy work\
  again.** Every save now keeps the last 5 versions of a file in the\
  app's own storage before overwriting it. A new "Backups" option in\
  the File menu lists available backups for the current file and\
  opens any of them as a new tab to review or recover — your current\
  file is never touched until you decide to.
* **Pasting from AI chat apps and webpages lost all formatting except\
  code blocks.** Bold, italic, links, inline code, headings, and\
  lists from the source were silently discarded on paste. Rich HTML\
  is now reconstructed directly using the same rules that already\
  define how each of those renders, so every kind of formatting the\
  app supports now survives a paste, not just code blocks.
* **"New Window" did nothing.** Now opens an actual second window\
  with a single blank document, independent of whatever's open\
  elsewhere — it doesn't restore your previous session or affect the\
  other window's saved session either.
* **Closing the original window after opening a new one didn't hand\
  off the saved session.** The new window's tabs now become the ones\
  restored next launch as soon as the original window actually\
  closes, instead of the old session staying stuck in place.
* **Editing a document with thousands of list items would freeze for\
  several seconds on every keystroke.** A markdown-formatting check\
  re-scanned the entire document's text on every single edit instead\
  of just the part that changed, so the cost grew sharply with\
  document size. A 17,000-item list went from a 35-second freeze per\
  keystroke down to under 100ms.
* **Pasting code from a "Copy code" button (rather than a manual\
  select+copy) landed as plain text, not a code block.** Those buttons\
  put only plain text on the clipboard, with none of the HTML structure\
  the existing rich-paste handling needs — pasted code that looks like\
  code is now detected and inserted as a real code block either way.
* **Pasted task lists lost their checked state, becoming plain lists.**\
  Pasted checkboxes are now read directly, not just this app's own\
  save-format attribute.
* **Pasted bold/italic/strikethrough/inline code looked correct but\
  never showed their markdown markers when the cursor was inside them**,\
  unlike typed formatting — and, separately, saved files contained\
  backslash-escaped markdown symbols for any *typed* formatting\
  (invisible inside Saguinus, but visible as literal backslashes in any\
  other markdown tool). Typing, pasting, and loading a file now all\
  produce the same representation, and saved files use clean markdown\
  syntax.
* **Nested lists (e.g. a numbered list containing a bullet list)\
  collapsed onto one line and lost their structure, both when typing\
  and when pasting** — most visibly when a nested list/quote/code block\
  was the very first thing inside a list item. Both the save format and\
  the paste-reconstruction logic now preserve the nesting correctly.
* **Pasted math (inline and block) from AI chat apps didn't show up at\
  all.** Block math is recovered from the KaTeX HTML these apps render\
  it as; inline math — which, unlike block math, often arrives as\
  literal `$...$` text rather than rendered HTML — is now recognized\
  too.
* **Page guides showed the wrong width on one side whenever the left\
  and right margins differed.** A single combined CSS rule sized both\
  guide strips off the left margin only — invisible while both margins\
  happened to match, now fixed so each side reads its own margin.
* **Critical: clicking into a math formula to edit it was unreliable** —\
  the cursor could land in the wrong spot, a second click could leave\
  it looking selected without actually being editable, and focus could\
  end up somewhere unexpected entirely. Math editing has been rebuilt\
  to work exactly like code blocks: typing into a formula now directly\
  edits real, native text with focus always where you'd expect,\
  instead of a separate hidden editor swapping in underneath the\
  cursor. Typing `$$` then Enter now also creates a new block formula\
  on the spot, the same way starting a code fence does.

## Verified (no change needed)

* Font family and font size selection from the toolbar apply correctly\
  across the whole document.
* Code block insertion already correctly moves the current selection into\
  the new block instead of deleting it.
